# Triage Labels

The skills speak in terms of five canonical triage roles. This file maps those roles to the actual label strings used in this repo's issue tracker.

| Label in mattpocock/skills | Label in our tracker | Meaning                                  |
| -------------------------- | -------------------- | ---------------------------------------- |
| `needs-triage`             | `needs-triage`       | Maintainer needs to evaluate this issue  |
| `needs-info`               | `needs-info`         | Waiting on reporter for more information |
| `ready-for-agent`          | `ready-for-agent`    | Fully specified, ready for an AFK agent  |
| `ready-for-human`          | `ready-for-human`    | Requires human implementation            |
| `wontfix`                  | `wontfix`            | Will not be actioned                     |

When a skill mentions a role (e.g. "apply the AFK-ready triage label"), use the corresponding label string from this table.

Edit the right-hand column to match whatever vocabulary you actually use.

## In this repo

Both columns are identical, so nothing needs translating: write the role name verbatim. These are **real GitHub labels** on `nathanihlenfeldt/aes67-srt`, not a convention recorded in file headers — `/triage` applies them with `gh issue edit <n> --add-label <role>`.

- `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human` were created by `/setup-matt-pocock-skills`.
- `wontfix` was a stock GitHub label from repo creation; this setup rewrote its description to match the role. It is not a new label.

Verify the set at any time:

```
gh label list --repo nathanihlenfeldt/aes67-srt
```

## Category roles

`/triage` also assigns exactly one **category** role per issue, `bug` or `enhancement`. Both are stock GitHub labels and already exist — apply them as-is, don't create variants. `bug` is correct only when something that exists is broken; a ticket describing work on a system that does not exist yet is `enhancement`.

Category is a separate axis from state: an issue should carry exactly one category label and one state label. GitHub enforces nothing here, so a mistyped or duplicated role won't error — check what `/triage` applied rather than assuming it landed.

## Closure is not a role

Closing an issue is GitHub's own open/closed state, not a sixth label — the same distinction the five-role vocabulary draws elsewhere. A closed issue keeps its state label, because the labels record what triage decided, not whether work is outstanding. To find outstanding work, filter on open issues:

```
gh issue list --state open --repo nathanihlenfeldt/aes67-srt
```

## Reading the tracker by hand

There is no separate triage record to reconcile — the labels are the state. To find what needs attention:

- **Unlabeled** — `gh issue list --search 'no:label'` (never triaged).
- **`needs-triage`** — `gh issue list --label needs-triage`
- **`needs-info` needing re-evaluation** — the issue has reporter activity after the last triage comment, so it's worth re-reading rather than trusting the label.

Triage comments are ordinary GitHub comments and must open with `> *This was generated by AI during triage.*`
